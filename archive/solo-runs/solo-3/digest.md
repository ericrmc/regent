## Ideas he declined, and why

- After each run it remembers the dead links it found, in one small plain file inside the folder it checked (say .linkcheck-last). Next run, each dead line that wasn't on the list last time gets 'NEW' at the front, and the count line adds 'N new since last run'. The Rings link stays listed every time and never gets NEW after the first run. I don't have to mark or ignore anything, and it never hides a line. Why: It would make the tool write a hidden file into my notes folder. I don't want that, and I don't want to mark or manage a list. I accepted that the Rings link shouts on every run.
- A 'waiting on purpose' list, like a .gitignore. If the notes folder holds a plain file called .waiting, with one missing note name per line (say Family), then dead links to those names are not counted as dead. They print in their own short block after the count: 'Waiting on purpose: Family: 3 links, in Rings.md, ...'. The count line says it in words: '2 dead link(s), 3 waiting.' It stays honest both ways. Only 'no such note' links can be waited on, never a heading miss. A name in .waiting that now exists as a note is called out at once: 'Family is on the waiting list but the note exists now, take it off.' A name in .waiting that no link points to is called out too, so the list can't go stale and hide something. The line count and the list are all in the one file. The .waiting file is copied by --copy-to like any other file, so Kieran sees it, and it is never treated as a note. Why: I said I'd let Rings shout on every run, and req-02 says no ignore list. A list of names to stay quiet about is one more file to keep and one more way to hide something. Kieran's copy already turns dead links into plain words, so the shouting stays in my folder.

## What he remembers of the project

Eric developed a link checker tool across multiple rounds. Early versions handled Polish characters, broken shortcuts, and path resolution issues. By round nine, it tracked missing notes and their references, orphaned files, and code blocks, though code block validation was initially incomplete. Round ten streamlined the code, fixed file handling, and added a copy-to feature that creates fresh note copies while resolving shortcuts but leaving broken links unchanged.

Round eleven added a progress line printed at the end of every run showing how many notes were read, plus usage text naming the --print and --copy-to flags. This required adjusting test expectations, but all tests passed. The code grew to 559 lines.

Round twelve involved reviewing the implementation to confirm the copy operation works correctly—refusing when targets exist or fall inside the notes folder, never modifying source files, and always printing its confirmation line.

Still pending: testing against real notes to verify whether the reported dead links are genuine issues, and clarifying what happens if a copy operation fails partway through, potentially leaving an incomplete folder.
